## Команды

Из корня проекта:

```powershell
npm test
npm run lint
npm run build
```

`npm run typecheck` — отдельная быстрая проверка типов. `npm run build` также включает TypeScript. Для проверки production остановить dev-сервер на том же порту и выполнить `npm start`.

При изменениях локального рендера отдельно `npm run video:test-render`: нужны FFmpeg/ffprobe; используются технические материалы без облачной генерации. Для изменений только документации достаточно проверить ссылки, актуальность лимитов/инструкций и `git diff --check`. Проверки, которые не запускались в текущем шаге, не записывать как свежий результат.

## Короткая бесплатная проверка приложения

1. **Навигация:** «Мои ролики → Новый ролик → Мои ролики», затем создание через профиль. При ошибке использовать «Повторить загрузку»; сетевой сбой не должен означать выход из аккаунта.
2. **Профили:** создать два разных, проверить язык/формат нового ролика и вариант «Без профиля». Изменить профиль — прежний ролик и версии сохраняют копию требований. Устаревшая вкладка не должна перезаписывать профиль. Конструктор хуков дописывает текст только по кнопке; при переполнении/дубликате прежний ввод остаётся.
3. **Версии:** в тестовом ролике сохранить две ручные/тестовые версии; первая не меняется. Настройки новой версии берутся из проекта, сцены старой не переносятся автоматически.
4. **Сцены и кадры:** редактирование, перестановка и сохранение относятся к выбранной версии. Кадры остаются у своего эпизода при перестановке. Удаление эпизода с кадрами требует подтверждения; отмена сохраняет данные.
5. **Публикация и экспорт:** проверить ручные/тестовые заголовки и описание, TXT/Markdown с кириллицей, переносами, источником и номером версии. Экспорт содержит сохранённые данные; копирование текста редактора может включать несохранённые правки.
6. **Доступ:** выйти и открыть защищённый адрес — нужен вход. Во втором аккаунте проверить ссылки проекта/версии/кадров первого: чужие тексты не должны быть доступны. Сетевая ошибка не доказывает запрет доступа.
7. **Удаление:** только отдельный ненужный проект, после явного подтверждения. Отмена оставляет его. Удаление облачных материалов не удаляет локальные видеофайлы; Git не восстанавливает записи БД.

Бесплатные тестовые шаблоны механические: они не показывают качество новых промптов Yandex и не исследуют тему.

## Медиа и реальные модели

Не включаются автоматически в обычные проверки кода. Сначала согласовать конкретный запрос и расходы, проверить аккаунт/баланс. Сохранение результата не должно повторно вызывать модель. После неопределённого сетевого результата сначала проверить состояние задания/кабинет; тайм-аут не доказывает отсутствие списания.

Приёмка короткого MP4: весь текст слышен, кадры соответствуют речи, субтитры включаются/выключаются, импортированный клип движется и не подмешивает свой звук, тайминги не расходятся. Замена изображения сохраняет озвучку/другие кадры; пересборка использует готовые материалы. Проверить перезапуск обработчика и сохранность завершённых стадий. Источники тестовых и настоящих материалов должны различаться.

Качество текста оценивается по реальному ответу: конкретное начало, новое содержание в каждом блоке, выполненное обещание финала, факты и заголовок без выдуманных обещаний. Оценки просмотров и вирусности не гарантируются.

## Если соединение нестабильно

- `[supabase] database/auth read timeout; attempt 1/2` — первая попытка чтения завершилась тайм-аутом. Вторая может восстановить загрузку. Это диагностическое предупреждение, не подтверждение успешного ответа.
- Обычный HTTP 200 страницы тоже не доказывает, что данные загружены: страница может содержать сообщение об ошибке. Проверять интерфейс вместе с логом.
- Сбой страницы после POST не означает, что запись не сохранена. Сначала повторить загрузку и проверить библиотеку/версию, затем решать о новой записи.
- `Failed to set fetch cache … ECONNRESET` — соединение оборвалось при чтении ответа для кэша Next.js. В режиме разработки отключён кэш HMR через next.config.ts. Это не устраняет нестабильность VPN и не доказывает причину 71-секундного ожидания.
- Тайм-аут транспорта ограничивает отдельный HTTP-запрос; несколько обращений, обработка тела ответа и внутреннее поведение SDK/Next могут увеличить время страницы. Для оставшихся задержек нужны время, адрес страницы без секретов, строки `[supabase]` и актуальный режим VPN. Полные ключи/cookies не присылать.

## Известные ограничения

- Нет автосохранения черновиков. Защита ухода не покрывает все формы и браузерные «Назад/Вперёд». Работать с одним редактором проекта за раз.
- Сцены и публикационные материалы изменяемы без истории; конфликтующие вкладки могут заменить данные. Защита устаревшего профиля не решает все конфликты приложения и не блокирует повторные платные запросы из разных вкладок.
- Профиль применяется к новым роликам. Смена текущего профиля не переносит требования в уже созданный проект. Селекты конструктора — шаблон для текста format, а не отдельные сохранённые настройки.
- Идеи живут в форме до применения; собственного архива идей нет. Источник материала не является доказательством авторства или фактической достоверности.
- Разные лимиты редактора и производства перечислены в [архитектуре](architecture.md#текущие-пределы) и [плане видео](video-production-plan.md#реальные-границы). Часовой рендер, полный длинный пилот и восстановление всех длительных операций не проверены.
- Удаление облачного проекта не чистит локальные медиа и не отменяет ранее подтверждённую задачу. Автоматической очистки локальных файлов нет.
- Оценка стоимости не является жёстким лимитом биллинга. Фактический расход Yandex неизвестен. Условия внешних сервисов проверяются перед использованием.
- Runway OAuth хранится локально без дополнительного шифрования Windows; реальный вход/каталог пользователем ещё не подтверждены. Автоматическая генерация Runway/Veo отсутствует.
- Нет автоматической проверки фактов, прав на материалы, монетизации и публикации YouTube. Восстановление пароля и публичная эксплуатационная безопасность не приняты.
- В старом npm audit были high-находки цепочки ESLint; свежий аудит на этом шаге не проводился. История — [архив проверок](archive/2026-10-19-testing.md#известные-ограничения). Публичный запуск не объявляется готовым.

## Проверка шага «Документация»

Перезапустить `npm run dev`, проверить несколько переходов и сохранение одного тестового ролика. Отдельно отметить, повторяется ли именно `Failed to set fetch cache` и длительные задержки. 20 октября прошли: ESLint для next.config.ts, загрузка конфигурации в режиме development с подтверждённым serverComponentsHmrCache=false, production-сборка с TypeScript, git diff --check. Проверены 135 локальных ссылок/якорей и полнота четырёх архивных копий: ошибок нет. Полный набор из 128 тестов повторно не запускался: логика приложения на этом шаге не менялась.

Сборка завершилась с двумя предупреждениями Turbopack о динамическом доступе к файлам в src/lib/production/store.ts (productionRoot/listJobs): анализатор может включить весь проект при упаковке. Это нужно проверить до внешнего развёртывания; код хранения в рамках чистки документации не менялся. Исчезновение пользовательского ECONNRESET и задержки 71 секунду этим прогоном не подтверждено.


## Проверка шага «Flow и экран Видео»

Локально: 128/128 тестов, TypeScript, ESLint и production-сборка прошли. Первый запуск тестов внутри Windows-песочницы получил EPERM при переименовании временных job.json; повтор без этой изоляции прошёл. Сборка сохраняет прежние предупреждения Turbopack о динамических путях store.ts.

Браузерная проверка настоящих компонентов с подставными ответами прошла на ширине 1414 и 360 px: переключение шагов, сохранность черновика, общая кнопка сохранения, раздельные промпты камеры, доступ к подтверждению расходов и отсутствие лишних вызовов. Горизонтального переполнения нет; скриншоты просмотрены. Это проверка интерфейса, не облачного API или качества материалов.

Ручная приёмка: открыть существующую сборку → «Кадры и движение»; изменить описание, переключиться на «Озвучка и сборка» и обратно — черновик остаётся, доступна кнопка сохранения. После сохранения раскрыть «Анимировать кадр N в Flow», выбрать камеру, проверить скопированный промпт, скачать изображение. Любой уже имеющийся подходящий MP4 можно загрузить здесь же в выбранную сцену; проверить сохранность других кадров и озвучки, затем локальную пересборку с выбранным режимом субтитров. Покупки и новая генерация для проверки интерфейса не нужны.

Реальная генерация Flow, расход кредитов и автоматическое управление браузером на этом шаге не проверяются и не считаются реализованными. Выбор камеры — временная подготовка промпта, не сохранённая настройка сборки.
