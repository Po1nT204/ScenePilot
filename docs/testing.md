## Команды

Из корня проекта, без реальных запросов к Yandex:

```powershell
npm test
npm run lint
npm run typecheck
npm run build
git diff --check
```

Сборка также проверяет TypeScript. npm test запускает локальные проверки валидации проектов, профиля, идей, сценариев и сцен, тестовых генераторов, экспорта, SQL-разделителей и адаптера Yandex с подставными HTTP-ответами. Эти тесты не проверяют облачную RLS. Проверки навигации отдельно проверяют сохранение идентификатора версии в ссылках и отсутствие переходов к несохранённым материалам.

На Windows/OneDrive сборка в ограниченной среде ранее завершалась `failed to canonicalize path`, `os error 5`. Повторная сборка вне ограниченной среды проходила; это не повод менять исходники или обходить проверки доступа приложения. ESLint в этой среде может выполняться несколько минут.

После её применения вставить подробный профиль Beyond the Scenario, сохранить и обновить страницу: полный текст должен остаться. На странице нового ролика длинные тон/формат не должны переполнять короткие поля; тестовые идеи должны применяться. SQL-тест профиля дополнен проверкой сохранения 1000 и отклонения 1001 символа для каждого из трёх полей; он ещё не выполнен в облаке.

1. Выполнить ещё не применённые миграции профиля по [setup.md](setup.md), включая расширение лимитов, затем открыть «Профиль канала». Заполнить поля и сохранить. Обновить страницу: профиль сохранился. У второго аккаунта свой пустой/отдельный профиль.
2. Открыть «Новый ролик»: язык заполнен из профиля, жанр и стиль — только если исходные требования не длиннее 100 символов; иначе видна подсказка заполнить короткие названия. Тему можно задать самостоятельно. Нажать «Тестовые варианты · бесплатно»: появляются три явно обозначенных шаблона; ролик ещё не создан.
3. Выбрать вариант: поля формы заполнены. Исправить название и тему, выбрать другой вариант и отменить замену — свои поля остаются. Подтвердить замену — меняются только четыре поля замысла. Изменить язык/длительность после генерации: применение прежних вариантов блокируется до возвращения параметров или нового запроса.
4. Создать ролик. В настройках видны источник замысла «Тестовый шаблон» и копия требований канала. Обновить страницу: обе отметки остались. Написать сценарий вручную и сохранить: его источник «Ручной ввод», источник замысла отдельно «Тестовый шаблон».
5. Изменить профиль канала. Ранее созданный ролик и его версии сохраняют старые требования; новый ролик получает новые. Экспорт старой версии содержит её копию профиля и источник замысла. Старые версии, сохранённые до миграции, по-прежнему открываются и экспортируются без профиля.
6. В двух вкладках: открыть форму нового ролика, затем изменить профиль в другой вкладке. Генерация/создание со старой формой должны предложить обновление, не обращаться к модели. Это обнаружение изменения updated_at, не полная защита от одновременной записи; для обычной работы используйте одну вкладку.
7. Под аккаунтом без профиля создать ролик вручную и проверить тестовые идеи: сохранённого профиля нет, сценарий по-прежнему доступен. До миграции страницы профиля/создания показывают инструкцию настройки, а не имитацию сохранения.
8. Проверить пустые поля, пределы длины, русский/английский, 360-пиксельное окно и клавиатуру. Генерация не должна создавать запись автоматически. Ошибки не должны стирать заполненные поля.

Новая SQL-проверка: [channel_profiles_rls.sql](../supabase/tests/channel_profiles_rls.sql). Подставить UUID двух тестовых пользователей и выполнить файл целиком. Она временно меняет профиль тестового аккаунта внутри транзакции и завершает ROLLBACK. Ожидаемый итог: `Channel profile checks passed; test changes rolled back`. Проверяет чужое/анонимное чтение и запись, запрет подмены владельца и снимка, сохранность копии после изменения профиля, использование нового профиля новым проектом и закрытый внутренний writer версий. Агент в облаке её не запускал. После изменения writer также повторить прежние SQL-тесты версий и сцен.

Реальные идеи проверяются отдельно только после согласования: один запрос, отмена подтверждения, три варианта, источник YandexGPT, ошибка без замены формы, сохранение без нового обращения к модели. Ограничения ответа и отсутствие повторов проверены локально подставными ответами.

## Приёмка общей рабочей области

1. Открыть ролик с двумя версиями. В сценарии раскрыть историю и выбрать старую версию. Перейти «Сцены → Экспорт → Настройки → Сценарий». Номер и version в URL остаются прежними.
2. Из настроек выбранной старой версии нажать «Изменить настройки», затем «Отмена»: контекст версии сохраняется. Повторить с изменением названия и сохранением: заголовок показывает новое название, выбранная версия прежняя. Экспорт сохраняет название из снимка старой версии.
3. Изменить сценарий и сохранить новую версию. Её номер появляется в панели; сцены пустые. Переключиться обратно на старую: её текст и сцены прежние.
4. Ввести несохранённую правку сценария или сцены, нажать другую вкладку, отменить уход: текст остаётся. Подтвердить уход: экспорт использует сохранённое состояние. Браузерные «Назад/Вперёд» остаются известным ограничением.
5. Открыть ролик без версий: «Настройки» и «Сценарий» доступны, «Сцены» и «Экспорт» не являются ссылками; объяснение доступности видно.
6. Подставить в version UUID другого проекта, включая собственный другой проект: ожидать not-found, без молчаливого переключения на последнюю версию. Повторить с невалидным UUID.
7. Проверить ширину 360 пикселей, длинное название, Tab/Enter, видимый фокус, выделение текущего раздела. Панель переносится, нет горизонтальной прокрутки.

## Библиотека

Проверить прямой переход к сценам и экспорту последней версии, нулевое число сцен новой версии, обновление счётчика после сохранения сцен и отсутствие чужих проектов под вторым аккаунтом. Пустой аккаунт показывает приглашение создать ролик. Ошибка запроса не должна выглядеть как пустая библиотека. Настройки и логотип доступны независимо от материалов.

## Сквозной путь без платных запросов

1. Войти под аккаунтом А, создать тестовый проект, обновить страницу. Изменить настройки и проверить их сохранение.
2. Ввести сценарий вручную или получить бесплатный тестовый шаблон; до сохранения версия не появляется. Сохранить две версии и проверить неизменность первой.
3. Изменить настройки проекта: снимок старой версии остаётся прежним; новая версия получит текущие параметры.
4. Создать бесплатные тестовые сцены для выбранной версии, изменить все три поля одной сцены, сохранить и обновить страницу. Проверить независимость набора другой версии.
5. Отменить подтверждение повторной генерации: редактор не изменился. При ошибке сохранения текст должен оставаться в редакторе; перед повтором проверить сохранённый результат.
6. Экспортировать TXT и Markdown. Проверить кириллицу, ё, переносы, длинный текст, обратные кавычки и HTML как текст, номер версии, настройки и источники. Проверить копирование и пустой набор сцен. Изменённые в другой вкладке сцены появятся после обновления экспорта.
7. Выйти, открыть защищённый адрес: ожидается вход. Войти снова: данные сохранились.
8. Удаление проверять только на отдельном ненужном проекте с подтверждением. Проверить исчезновение и недоступность его старых адресов. Откат Git не восстанавливает удалённые записи БД.

## Два аккаунта и SQL

Под аккаунтом Б в отдельном приватном окне открыть ссылки проекта А, настроек с edit=1, сценария, сцен и экспорта. Ожидается отсутствие доступа без чужих названия, текста и сцен. HTTP 500 и ошибка сети не доказывают запрет. Создать собственный проект Б и проверить, что А его не видит.

После миграций из [setup.md](setup.md) выполнить в Supabase SQL Editor по одному полному файлу:

| Файл | Сообщение об успехе |
| --- | --- |
| [projects_rls.sql](../supabase/tests/projects_rls.sql) | RLS checks passed; test changes rolled back |
| [script_versions_rls.sql](../supabase/tests/script_versions_rls.sql) | Script version checks passed; test changes rolled back |

Подставить разные UUID двух тестовых пользователей вместо REPLACE_WITH_USER_A_UUID и REPLACE_WITH_USER_B_UUID. UUID берутся в Authentication → Users; секреты для теста не нужны. Скрипты создают временные данные внутри транзакции, проверяют владельца, чужой и анонимный доступ, ограничения записи и заканчиваются ROLLBACK. Строка source=yandex не вызывает модель. При ошибке сохранить безопасный текст ошибки; если транзакция осталась открытой, выполнить ROLLBACK. Не повторять миграции и не удалять таблицы ради ошибки теста.

## Реальный Yandex

Только после отдельного согласования конкретной проверки и расходов: короткий сценарий → один запрос → проверка полноты и языка → сохранение без нового запроса → проверка источника после перезагрузки. Для сцен — отдельный запрос по сохранённой версии, проверка смысла и порядка, сохранение. Биллинг сверить с учётом задержки. Сбой/тайм-аут не равен бесплатному запросу. Автоматические тесты ошибок 401/403/429, неверного/оборванного ответа и сетевых отказов используют подставные ответы.

## Известные ограничения

- Черновики автоматически не сохраняются. Ссылки и перезагрузка предупреждают о правках сценария/сцен, но браузерные «Назад/Вперёд» могут обойти предупреждение. Форма настроек не имеет полноценной защиты несохранённого ввода.
- Одна вкладка на проект: конкурентное сохранение сцен может заменить другой набор; защита от повторных платных запросов между вкладками отсутствует.
- Сцены внутри версии изменяемы, истории их правок нет. Проверка структуры ответа не гарантирует фактическую достоверность и смысловую полноту.
- Ограничения длительности и объёма перечислены в [architecture.md](architecture.md). Для длинного текста есть ручной путь и оценка озвучки, но генерация полного длинного сценария/сцен и реальный пилот ещё не проверены; оценка времени не равна записи диктора.
- Фактический расход Yandex неизвестен; жёсткого денежного лимита в приложении нет.
- Результаты идей живут в текущей форме и не имеют собственной истории; после создания сохраняются выбранные поля и источник. Замысел не равен описанию YouTube. Профиль применяется к новым роликам, перенос в существующие пока отсутствует.
- Материалы публикации изменяемы без истории и защиты от одновременной записи двух вкладок. Их источники относятся ко всему набору и сохраняются при ручной правке. Автоматической проверки фактов, таймкодов, внешних ссылок и публикации на YouTube нет. Скопированный текст может включать несохранённые правки, экспорт — только сохранённые.
- В первом спринте npm audit сообщал пять high-записей цепочки eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces (GHSA-vfj7-8cjw-p6xm). Это прежний результат, не свежий аудит. Автоматический откат eslint-config-next на 14.x не применяли. ESLint закреплён на 9.39.5; обновление инструментов требует отдельной совместимой проверки.
- Восстановление пароля, публичное размещение и эксплуатационная безопасность не приняты. Приложение не объявляется готовым к публичному запуску.
