## HTTP 400 при проверке голоса — 18 октября 2026

После переключения Happ в TUN пользователь сообщил: проверка подписки проходит, проверка голоса отвечает HTTP 400. Для выяснения причины выполнен один GET метаданных выбранного голоса с уже настроенным ключом, загруженным внутри процесса стандартным загрузчиком окружения. Выведены только HTTP-статус и распознанный код: `400 voice_not_found`. Отдельный GET контрольного голоса `JBFqnCBsd6RMkjVDRZzb` вернул HTTP 200 и подтвердил ID. Секрет не выводился, сырые ответы не публиковались, настройки аккаунта не менялись, синтез и платные запросы не выполнялись. Это подтверждает доступ к метаданным контрольного голоса, но не возможность синтеза/его качество.

Исправлена ошибочная общая подсказка «Сервис недоступен» для HTTP 400. Теперь читаются только известные коды из ограниченного ответа, поддерживаются `detail.code` и прежний `detail.status`. Для `voice_not_found` показаны My Voices/Copy voice ID и необходимость новой сборки после смены голоса. Неизвестные коды, HTML, слишком большие ответы и произвольные тексты не выдаются за конкретную причину. Четыре целевых теста прошли (15 остальных пропущены фильтром), TypeScript прошёл. Полный набор и визуальный интерфейс повторно не проверялись; разметка не менялась.

ESLint, production-сборка с TypeScript и git diff --check также прошли.

Дальше пользователю: перезапустить приложение, вставить проверенный контрольный Voice ID, нажать «Новая сборка» и повторить проверку без генерации. Для желаемого голоса — добавить его в My Voices, скопировать ID оттуда и создать ещё одну сборку. Приёмка настоящей озвучки остаётся открытой.

## Ошибка подключения через системный прокси — 18 октября 2026

Пользователь сообщил об общей ошибке проверки на бесплатном аккаунте и подтвердил режим «Системный прокси» в Happ. Проверено без ключа, без чтения `.env.local` и без генерации: Node.js v20.19.6, переменные прокси отсутствуют, системный прокси включён на локальном порту 10809. Первая проба Node завершилась TypeError без кода причины; отдельная следующая диагностическая проба вернула HTTP 403 напрямую, curl через уже включённый локальный прокси — HTTP 401. Это подтверждает различие маршрутов, но не валидность ключа и не точную причину первоначального сбоя приложения. Настройки сети и VPN-подписку агент не менял и не читал.

Проверка теперь различает этап подписки/голоса, неверный формат заголовка ключа, известные коды DNS/тайм-аута/соединения/TLS и не-JSON ответ. Неизвестные сетевые ошибки показываются без сырого текста и с пояснением про системный прокси. Прошли три целевых теста подключения (остальные 15 тестов файла пропущены фильтром), ESLint, TypeScript, production-сборка и git diff --check. Проверено отсутствие повторов и утечек для вложенных сетевых ошибок, некорректного ключа и HTML-ответа. Полный набор тестов на этом исправлении повторно не запускался.

Осталось пользователю настроить маршрут самого приложения (для Happ предложен TUN), перезапустить dev-сервер и нажать проверку без генерации. Ожидаются сведения о free-тарифе и голосе либо уточнённая ошибка. Реальный ключ, доступность выбранного голоса для синтеза и аудио остаются непроверенными. Покупка подписки для диагностики не требуется.

## Известные ограничения

- Черновики автоматически не сохраняются. Ссылки и перезагрузка предупреждают о правках сценария/сцен, но браузерные «Назад/Вперёд» могут обойти предупреждение. Форма настроек не имеет полноценной защиты несохранённого ввода.
- Одна вкладка на проект: конкурентное сохранение сцен может заменить другой набор; защита от повторных платных запросов между вкладками отсутствует.
- Сцены внутри версии изменяемы, истории их правок нет. Проверка структуры ответа не гарантирует фактическую достоверность и смысловую полноту.
- Ограничения длительности и объёма перечислены в [architecture.md](architecture.md). Для длинного текста есть ручной путь и оценка озвучки, но генерация полного длинного сценария/сцен и реальный пилот ещё не проверены; оценка времени не равна записи диктора.
- Фактический расход Yandex неизвестен; жёсткого денежного лимита в приложении нет.
- Результаты идей живут в текущей форме и не имеют собственной истории; после создания сохраняются выбранные поля и источник. Замысел не равен описанию YouTube. Профиль применяется к новым роликам, перенос в существующие пока отсутствует.
- Материалы публикации изменяемы без истории и защиты от одновременной записи двух вкладок. Их источники относятся ко всему набору и сохраняются при ручной правке. Автоматической проверки фактов, таймкодов, внешних ссылок и публикации на YouTube нет. Скопированный текст может включать несохранённые правки, экспорт — только сохранённые.
- В первом спринте npm audit сообщал пять high-записей цепочки eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces (GHSA-vfj7-8cjw-p6xm). Это прежний результат, не свежий аудит. Автоматический откат eslint-config-next на 14.x не применяли. ESLint закреплён на 9.39.5; обновление инструментов требует отдельной совместимой проверки.
- Восстановление пароля, публичное размещение и эксплуатационная безопасность не приняты. Приложение не объявляется готовым к публичному запуску.

### Бесплатная ручная проверка

1. Создать проект с целью **30 секунд**. В сценарии раскрыть «Темп и расчёт», установить **140**: ориентир **70 слов (63–77)**. Изменить на **160**: **80 слов (72–88)**. Ввод 79, 221 или дроби должен блокировать сохранение/генерацию и показывать ошибку.

4. Переместить кадр вверх, сохранить и обновить: поля идут вместе с кадром, порядок сохраняется, сравнение замечает перестановку фраз. Вернуть порядок. Попробовать пустое обязательное поле и длительности 0/61: сохранение недоступно. Отменить удаление кадра — список не меняется.

6. На тестовом эпизоде проверить удаление: предупреждение явно упоминает потерю кадров; отмена сохраняет набор. Подтверждённое удаление применяется только после «Сохранить сцены». Генерация замены набора с кадрами отключена. Не проверять удаление на нужных материалах.

Проверить общее/отдельное копирование и скачанный TXT. «Визуальные промпты» по-прежнему экспортирует эпизоды; «Текст озвучки» — точный сохранённый сценарий; «Полный архив» TXT/Markdown содержит темп, источники, поля и длительности кадров. Несохранённые правки не включаются. Версия без кадров показывает пустое состояние, без пустого файла.
8. Сохранить новую версию сценария: сцены/кадры старой не переносятся. Вернуться к старой: её материалы доступны. Во втором аккаунте открыть прямой адрес кадров первого: доступа нет. Подставить sceneId другой версии своего проекта: тоже нет доступа.
9. Проверить Tab/Shift+Tab/Enter, видимость фокуса, ширину 360, сохранение внизу длинного списка; предупреждение при уходе с правками. При ошибке записи текст должен остаться в редакторе. «Назад/Вперёд» браузера и конкурентные правки списка остаются известными ограничениями.

### Проверка базы

После миграций выполнить целиком [scene_shots_rls.sql](../supabase/tests/scene_shots_rls.sql), заменив REPLACE_WITH_USER_A_UUID и REPLACE_WITH_USER_B_UUID на разных существующих тестовых пользователей из Authentication → Users. Ожидается `Shot and pace checks passed; test changes rolled back`. Проверяются темп будущих снимков, прежний снимок, стабильные ID при перестановке, неверные/чужие связи, атомарный отказ, устаревшая озвучка, защита старых функций, подтверждение удаления и RLS. Файл откатывает тестовые данные. Затем повторить прежние [scenes_rls.sql](../supabase/tests/scenes_rls.sql) и [script_versions_rls.sql](../supabase/tests/script_versions_rls.sql). До фактического результата эти проверки не считаются пройденными.

### Следующий шаг после бесплатной приёмки

Сообщить результаты чеклиста/SQL и доступный остаток бюджета Yandex. Согласовать один конкретный запрос: например, английский сценарий 600 секунд при 140 слов/мин, ориентир 1400 слов, до 6000 токенов/90 секунд на yandexgpt-5.1. Проверить завершённость, фактическое отклонение, отдельное сохранение без нового запроса и биллинг. Отказ/тайм-аут не означает бесплатный запрос. Затем отдельная приёмка текста и позже отложенный пилот 8–12 минут с реальной озвучкой; генерация видео и внешние подписки не входят.
