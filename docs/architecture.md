# Архитектура ScenePilot

## Стек и границы

Одно приложение Next.js App Router + TypeScript содержит интерфейс и серверные действия. Supabase предоставляет Auth и PostgreSQL с RLS. YandexGPT вызывается только сервером. Локальному приложению нужен интернет для облачных операций. Для производства видео добавлены локальная файловая очередь и отдельный Node-обработчик; отдельного backend API, ORM и локальной БД нет.

В интерфейсе один «ролик» соответствует записи projects. Термины проекта и ролика не означают разные сущности.

| src/lib/production, src/app/projects/[id]/video, scripts/video-worker.ts | Локальные задачи видео, защищённая выдача файлов, ElevenLabs/BFL и FFmpeg |

## Локальное производство видео

Первый вариант: /projects/[id]/video?version=… создаёт отдельную локальную сборку из сохранённого сценария. Шесть групп текста покрывают нормализованную озвучку без пропусков; описания изображений редактируются. Существующие сцены и кадры в БД не меняются и автоматически в этот план не импортируются. Точный исходный сценарий, источник, владелец, проект, версия, голос и собственный план фиксируются в job.json. Для нового голоса создаётся новая сборка.

По умолчанию файлы находятся в %LOCALAPPDATA%/ScenePilot/production, вне Git, public и OneDrive; SCENEPILOT_MEDIA_DIR позволяет задать другой абсолютный путь. Хранилище рассчитано на один доверенный Windows-профиль, не на общий сервер. Серверные действия и маршрут assets проверяют вход, владельца проекта, принадлежность версии и локальной задачи. Выдача разрешена только для файлов, перечисленных в задаче; Range поддерживает просмотр/перемотку. service_role не используется. Новых таблиц Supabase нет.

Node-обработчик запускается отдельно, использует межпроцессную блокировку и последовательно выполняет сохранённые задания. Изменения JSON записываются через временный файл и переименование; редактирование защищено блокировкой и номером ревизии. До платного вызова на диск записывается попытка и её оценка стоимости. VIDEO_GENERATION_ENABLED по умолчанию выключен; запуск требует серверной проверки ключей, пользовательского подтверждения и предела оценки. Это не гарантированный денежный лимит у провайдера: реальные списания и налоги проверяются в его кабинете.

ElevenLabs Multilingual v2 возвращает MP3 и разметку исходного текста. FLUX1.1 pro возвращает ID и адрес проверки; сохранённый ID проверяется без повторного POST. Адреса API/файлов ограничены доверенными доменами. После сетевой неопределённости запрос не повторяется автоматически. При перезапуске running-задача становится failed, незавершённый запрос — pending при наличии ID/URL или unknown без него. Завершённые материалы сохраняются. Очередь ранее подтверждённых, ещё не начатых задач продолжает работу.

18 октября добавлена операция speech: только озвучка без ключа BFL, затем общий запуск использует сохранённое аудио. Для неё действуют те же подтверждение расходов, резервирование до запроса и запрет повтора после неопределённого результата. Ключи проверяются только для реально нужных провайдеров. Проверка подключения запускается отдельно пользователем после проверки владельца проекта/версии: два GET к фиксированным адресам ElevenLabs (подписка и Voice ID), без текста сценария, генерации и повторов. Ответ ограничен по размеру, каждый запрос — 15 сек.; клиент получает только название/ID голоса, тариф, остаток квоты и время проверки. Полные ответы, счета, ключи и ссылки на образцы не возвращаются. Эта проверка не доказывает разрешение TTS, доступность голоса для генерации, лицензию или лимит ключа.

FFmpeg обрабатывает по одному кадру, затем соединяет их с озвучкой и SRT, проверяет дорожки и длительность через ffprobe. Shell не используется. Сборка и скачивание не вызывают модели; замена картинки сохраняет голос и остальные кадры, прежний MP4 отмечается устаревшим. Промпт отправленного изображения фиксируется отдельно от последующих правок. Файлы прежних попыток сохраняются; автоматической очистки пока нет. Удаление облачного проекта не удаляет локальные файлы и не отменяет уже подтверждённую задачу; интерфейс предупреждает об этом.

Для ошибок проверки ElevenLabs читается не более 64 КБ JSON, распознаётся только фиксированный набор `detail.code`/`detail.status`. На клиент попадают известный код, локализованная подсказка и HTTP-статус; произвольные сообщения, идентификаторы запросов и сырые ответы не возвращаются. Неизвестный HTTP 400 обозначается как отклонённый запрос без выдуманной причины; повторов нет.

Текущие ограничения: 5000 символов нормализованного сценария, автоматический план до шести кадров, вывод 1280×720/24 fps, фактическая озвучка до 900 секунд. Точное совпадение таймингов с отправленным текстом проверяется до рендера. Движение изображений — не генерация видео моделью. Многочасовые ролики, загрузка своих медиа, облачный запуск обработчика, отмена активной задачи из интерфейса и автоматическое удаление старых файлов не реализованы.

Проверка BFL выполняется отдельно после проверки владельца проекта/версии: один GET `https://api.bfl.ai/v1/credits`, заголовок `x-key`, тайм-аут 15 секунд, не более 16 КБ ответа, без перенаправлений/повторов. Клиент получает только числовой баланс и время; тексты ошибок провайдера не возвращаются. Она доступна при выключенной генерации и без обработчика. Операция `replace` теперь доступна для пустого кадра, сохраняя озвучку и остальные изображения. До запуска проверяются согласие, оценка и незавершённая задача: pending/requesting или сохранённый polling URL запрещают замену. Только известный окончательный статус BFL переводит pending в failed и снимает URL; временная ошибка и неизвестный статус сохраняют возможность проверки. HTTP-ошибка проверки сама по себе не считается окончанием генерации. Общий запуск пропускает готовые файлы; UI показывает число сохранённых кадров.

## Данные

Пользователь → проекты → версии сценария → сцены/эпизоды → кадры.

- projects: владелец, название, тема, жанр, стиль, язык, целевая длительность, даты.
- После миграции 202610150001: projects.channel_snapshot — копия профиля при создании, brief_source — источник замысла (manual/test/yandex/unknown). Старые проекты получают null и unknown без переписывания текста.
- channel_profiles: несколько строк на owner_id, отдельный UUID id, название канала, аудитория, темы, тон, формат, нежелательные обороты, язык, updated_at. Собственный профиль читается/изменяется через сервер и RLS; owner_id менять запрещено.
- script_versions: проект, уникальный номер в проекте, текст, снимок настроек, источник, дата. Источники: manual, test, yandex, unknown для старых записей.
- scenes: версия сценария, позиция, описание, визуальный промпт, озвучка, источник manual/test/yandex. Источник хранится в каждой строке scenes, а не отдельным полем набора или версии.
- publication_materials: одна строка на script_version_id, выбранный title, массив titles (0–3), description, source manual/test/yandex, updated_at. Каскадно удаляется вместе с версией. Материалы изменяемы, текст и снимок самого сценария остаются неизменными.

Снимок содержит title, topic, genre, style, language и target_duration_seconds. После новой миграции будущие версии также получают channel и brief_source из проекта. Его создаёт БД одновременно с версией из текущих настроек проекта. Старые снимки без этих полей по-прежнему читаются и экспортируются.

## Обязательные инварианты

1. Текст и снимок сохранённой версии не изменяются. Сохранение правки создаёт новую версию; номер назначается в БД под блокировкой проекта.
2. Новая версия не наследует сцены автоматически. Все сцены принадлежат конкретной script_version_id.
3. Сцены внутри версии редактируемы. save_scene_edits_with_ids проверяет владельца, блокирует проект, сохраняет ID существующих сцен при правках/порядке, вставляет новые и удаляет отсутствующие. Удаление сцены с кадрами требует её ID в списке подтверждённых удалений. Старые save_scene_edits/save_scenes/save_test_scenes отклоняют замену при наличии кадров. Все записи атомарны.
4. История правок сцен не ведётся. Экспорт старого сценария использует текущий сохранённый набор его сцен, а не исторический снимок набора.
5. Экспорт использует сохранённый текст выбранной версии, только её сцены, кадры и материалы публикации. Полный архив включает настройки и метаданные; чистые режимы — только сценарий или visual_prompt. Несохранённый редактор и текущие настройки проекта в файл не входят.
6. Владелец берётся из сессии, не из браузера. Сервер проверяет проект и принадлежность версии, RLS повторяет ограничения при обращении к БД.
7. Внешние ключи и уникальные позиции обеспечивают связи; подтверждённое удаление проекта каскадно удаляет версии и сцены.
8. Источник материала сохраняется при ручной правке. Это метаданные происхождения, не криптографическое доказательство: допустимый source передаётся при сохранении авторизованным клиентом.
9. Снимок профиля присваивает BEFORE INSERT триггер проекта из собственного channel_profiles. Клиенту не выданы права вставки/изменения channel_snapshot. Изменение профиля не меняет существующие проекты и версии; автоматического переноса новых требований в старый ролик нет.
10. Материалы публикации читаются через RLS владельца проекта, записываются только через save_publication_materials с проверкой auth.uid(), принадлежности версии и блокировкой проекта. Прямая запись в таблицу закрыта. Сервер дополнительно проверяет пару projectId/versionId. Новая версия не наследует описание и заголовки.

## Профиль и помощник замысла

Профиль необязателен, но схема миграций профиля нужна для страницы создания. Основной язык предварительно заполняет язык ролика. Формат и тон заполняют жанр и стиль только если укладываются в предел этих коротких полей — 100 символов. Иначе поля остаются для ручного ввода, а тестовые идеи получают стандартные короткие значения. Подробные требования сохраняются целиком в снимке профиля. При генерации приоритет имеют явные настройки ролика. Аудитория, темы и нежелательные обороты передаются как дополнительные требования.

Помощник получает направление до 1000 символов, язык и длительность 1–900 секунд. Профиль выбирается явно по id либо отсутствует. Сервер фильтрует профиль по id и owner_id из сессии, сравнивает updated_at с прочитанным формой значением. При изменении/отсутствии профиля модель не вызывается. В модель попадают только творческие поля, без id, owner_id и updated_at.

Миграция 202610190001_multiple_channel_profiles.sql переводит первичный ключ профилей с owner_id на id, сохраняя RLS и ограничения записи колонок. Создание профиля — INSERT, редактирование — UPDATE по id + owner_id + updated_at: устаревшая форма не перезаписывает свежие правки. Клиент не может назначить/изменить id либо сменить владельца.

При создании projects получает channel_profile_id и channel_profile_revision. BEFORE INSERT проверяет auth.uid(), принадлежность профиля и точное совпадение revision, блокирует выбранный профиль FOR SHARE и формирует channel_snapshot. Это закрывает гонку между предварительной проверкой и записью. Для «Без профиля» оба поля и снимок равны null. Связь и revision нельзя менять клиентским UPDATE; удаление профиля через БД обнуляет связь, но сохраняет снимок. У прежних проектов новые поля null, их снимки и функции сохранения версий не меняются.

На странице нового ролика единственный профиль выбирается предварительно; при нескольких начальное значение «Без профиля», либо явный профиль из ссылки. Переключение профиля обновляет язык/короткие жанр и стиль и очищает форму/идеи; при правках требуется подтверждение. Во время сохранения или запроса идей переключение блокируется. Профили пока содержат только творческие требования: настройки провайдеров и ключи в них не хранятся.

Результат — ровно три варианта title/topic/genre/style. Лишние идентификаторы от модели отбрасываются, неправильный JSON или размеры отклоняются. Выбор варианта с подтверждением заменяет поля формы; пользователь редактирует их и отдельно создаёт ролик. При ошибке новые данные не заменяют форму. Изменение языка/длительности после получения вариантов блокирует их применение до согласования параметров. Источник замысла не меняется от ручных правок; он не подменяет источник сценария.

Требования канала передаются в реальный генератор сценария из проекта, в генераторы сцен и публикации — из снимка выбранной версии. Экспорт включает эту копию и источник замысла. Тестовые идеи — механические шаблоны, не исследование темы и не обещание успеха.

## Управление сценами

Редактор хранит временные стабильные ключи карточек, чтобы перестановка не смешивала текст полей. Клиентские ключи и позиции не передаются в запись. Сервер выделяет description, visual_prompt, narration, source и необязательный ID существующей сцены; RPC проверяет его принадлежность версии и отсутствие дублей. База назначает позиции 1..N из порядка массива. Новая сцена получает manual, генерация — test/yandex; редактирование и перестановка сохраняют источник. Источник — метаданные происхождения, не доказательство авторства.

Добавление, удаление и порядок меняют локальный черновик; запись происходит одной кнопкой. Удаление карточки требует подтверждения, сохранение пустого набора — дополнительного подтверждения очистки. Генерация по-прежнему требует 1–12 заполненных сцен, а ручной редактор сохраняет 0–12. Три поля обязательны для каждой непустой сцены. Истории и автоматического восстановления удалённых сцен нет. Экспорт и библиотека обновляются после сохранения; другие версии и сценарий не изменяются.

## Материалы публикации

Вкладка использует только сохранённый сценарий и его снимок, не несохранённый редактор, текущий профиль или сцены. Генератор получает whitelist творческих полей без идентификаторов владельца. Результат Yandex — ровно три разных заголовка и описание; неверный/оборванный ответ отклоняется без повтора и подмены шаблоном. Первый вариант подставляется в выбранный заголовок; его можно выбрать заново или изменить отдельно. Ручной ввод требует только заголовок и описание, варианты необязательны. Тестовый режим показывает явно обозначенный шаблон с фрагментом сценария, не выдаёт его за пересказ или исследование.

Генерация заменяет редактор после подтверждения. Сохранение выполняет upsert разрешённых полей через RPC и не вызывает модель. Источник набора сохраняется при ручных правках. Экспорт загружает только сохранённую строку выбранной версии; ошибка загрузки блокирует файл вместо молчаливой потери раздела. Отдельные кнопки копируют текущий текст редактора, включая несохранённый. Истории правок и защиты от перезаписи другой вкладкой нет; рекомендуется одна вкладка.

## Навигация по материалам

Библиотека /projects получает последнюю версию каждого собственного проекта и число её сцен без загрузки текстов. Из неё доступны прямые переходы к материалам.

Общий серверный компонент ProjectWorkspace показывает название ролика, выбранную версию и ссылки «Настройки / Сценарий / Сцены / Публикация / Экспорт». Он получает версию после проверки страницей. При переходах version остаётся в query string. Настройки без version выбирают последнюю версию, с version проверяют её принадлежность проекту. Редактирование, отмена и сохранение настроек сохраняют контекст версии; navigationVersion служит только для адреса возврата, не для записи данных.

Без сохранённого сценария сцены, публикация и экспорт недоступны, причина видна в панели. История версий находится в редакторе сценария. Ошибочный или чужой идентификатор не переключает пользователя молча на другую версию.

## Компактные редакторы

Сценарий и сцены показывают основное сохранение в верхней панели, источник и состояние черновика рядом с материалом. Для набора больше двух сцен сохранение также доступно внизу списка. Верхняя кнопка сцен связана с прежней формой через form/id: обязательные поля и обработчик сохранения остаются теми же. История версий остаётся доступной над сценарием; исторические настройки и профиль находятся в раскрываемом блоке после редактора.

NarrationMeter показывает слова, приблизительное время, цель и краткое отклонение. Темп, условность расчёта и дополнительные числа раскрываются в «Темп и расчёт». Ошибка темпа и несовпадение озвучки со сценарием видны и при закрытой справке. Темп сценария входит в снимок новой версии и задание генерации; в сценах изменение темпа меняет только локальную оценку. Платность обозначена на кнопках; блокировка длинной генерации, ошибки и предупреждения об уходе/замене/удалении не скрыты в справке. Шаг 2 менял представление; шаг 3 отдельно добавил сохранение темпа.

## Режимы экспорта

Сервер страницы экспорта проверяет пользователя, владельца проекта и пару projectId/versionId, затем загружает сохранённую версию, её сцены, кадры, снимки планов и публикацию. Ошибка чтения блокирует экспорт; она не выдаётся за отсутствие материалов. Во всех режимах общий сериализатор проверяет принадлежность сцен и публикации версии и отсутствие повторных позиций. RLS остаётся вторым уровнем защиты.

- «Текст озвучки» (режим по умолчанию) возвращает content версии буквально: без добавленного заголовка, метаданных, обрезки пробелов и конечного переноса. Если сам сохранённый сценарий содержит инструкции или заголовки, экспорт их не распознаёт и не удаляет.
- «Визуальные промпты» возвращает только visual_prompt, сортируя сцены по position и разделяя их пустыми строками и `---`. Отдельная кнопка копирует один промпт буквально, без разделителя и номера. При отсутствии сцен видна причина; предпросмотр, копирование и скачивание пустого пакета отсутствуют. Озвучка и архив остаются доступны.
- «Промпты кадров» возвращает visual_prompt кадров по порядку эпизода и кадра; отдельное копирование без оформления. При отсутствии кадров готовый пакет не формируется.
- «Полный архив» добавляет кадры и темп к прежнему содержимому TXT/Markdown: текст, снимок настроек, UUID, номер/дату версии, источники, все поля сцен и публикацию, включая явные сообщения об отсутствующих материалах.

Предпросмотр, общий буфер обмена и файл используют одну вычисленную строку выбранного режима и формата из одних серверных данных. Чистые режимы скачиваются как UTF-8 TXT; архив — TXT или Markdown. Файлы без добавленного BOM, чтобы чистая озвучка совпадала с сохранённым текстом. Версия и источник сценария видны около действий; у промптов доступны источники сцен. Происхождение из базы не удаляется. При запрете буфера выделяется соответствующее поле для ручного копирования. Изменения другой вкладки появятся после обновления страницы; совместимость с конкретным видеосервисом не гарантируется.

## Генерация и сохранение

- Сценарий: текущие настройки проекта → проверка доступа → тестовый генератор или Yandex → проверка результата → редактор → отдельное сохранение версии.
- Сцены: сохранённый текст выбранной версии и её снимок → проверка доступа → генератор → валидация всего набора → редактор → отдельное сохранение сцен.
- Ошибка запроса оставляет редактор без замены. Сохранение не вызывает модель. Автоматических повторов и скрытого тестового ответа нет.
- Yandex использует server-only, фиксированный HTTPS endpoint, no-store и x-data-logging-enabled:false. Email, сессия и секреты не включаются в промпт; тело ошибок API не показывается пользователю.

## Текущие пределы

Для длинного пилота цель проекта расширена до 900 секунд отдельной миграцией ограничения projects. Это не увеличивает размер сценария и число сцен. Для цели 301–900 секунд согласован один запрос сценария к yandexgpt-5.1 с максимумом 6000 токенов и 90 секунд. Длинные сцены Yandex по-прежнему заблокированы до HTTP-запроса; идеи и материалы публикации сохраняют прежние лимиты. Ручной ввод и бесплатное механическое разбиение работают с текстом до 20 000 символов.

Оценка озвучки — локальная формула `число слов / выбранный темп × 60`. Темп по умолчанию условно 140 слов/мин, допустимы 80–220; это ориентир, не измерение реального диктора. save_script_version_with_pace добавляет narration_pace только в снимок новой версии через существующий защищённый writer. У старых версий поле отсутствует, UI сообщает об этом и использует 140 для оценки. Старый RPC совместим. Перед платным запросом проверяется доступность миграции через script_pace_ready. Заголовки/инструкции не распознаются и тоже считаются словами. Отклонение более 20% от цели помечается как короткий/длинный текст. В сценарии цель берётся из текущего проекта (для будущей версии), при отличии от снимка показаны обе цели. В сценах цель берётся только из снимка выбранной версии. Сравнение конкатенации озвучки со сценарием игнорирует только пробелы/переносы; не гарантирует смысловую полноту, фактическую точность или готовность монтажа.

Материалы публикации: заголовок и каждый вариант до 100 символов, описание до 5000, до трёх вариантов; модель должна вернуть ровно три разных. Вход Yandex — до 30 000 символов JSON, выход — до 2000 токенов. Лимиты приложения повторены в проверке RPC; это не проверка фактической достоверности или гарантия качества для YouTube.

Профиль: название до 120, аудитория до 400, темы/тон/формат/нежелательные обороты до 1000 символов каждое. Лимиты формы и серверной проверки задаёт channelLimits, ограничения базы обновляет отдельная миграция 202610150002_channel_profile_limits.sql. При их изменении нужно согласовывать оба уровня.

Длительность проекта 1–900 секунд; сценарий до 20 000 символов; до 12 сохранённых сцен с тремя обязательными полями до 2000 символов каждое. Языки ru/en. Запрос сценария: до 6000 символов JSON без профиля или 9000 с профилем; до 2000 токенов ответа для цели ≤300 секунд, 6000 для 301–900 только на 5.1. Запрос сцен: до 24 000 символов JSON без профиля или 27 000 с профилем; до 4000 токенов ответа. Запрос идей: до 6000 символов JSON и 2000 токенов ответа. Тайм-аут 45 секунд (90 для длинного сценария), автоматических повторов нет. Длительность — ориентир, не точный хронометраж.

Нет автосохранения черновиков, истории правок сцен, защиты от конфликтов вкладок и денежной блокировки бюджета. Полный список ограничений и проверки — в [testing.md](testing.md).

## Сменные модули изображений

Оформление сборки хранится в необязательных `visualStyle` и `subtitlesEnabled`: для старых файлов используются исходный промпт и включённые субтитры. Серверное действие проверяет владельца/версию, ревизию, блокировку и допустимые значения. Смена субтитров отмечает существующий MP4 устаревшим; FFmpeg при следующем рендере исключает фильтр наложения, сохраняя голос и файлы кадров. SRT продолжает формироваться из таймингов. Смена стиля не меняет уже готовое изображение или его источник и не требует пересборки до замены кадра.

`visual-style.ts` составляет промпт независимо от провайдера. Исходное описание остаётся редактируемым, фактически отправленный текст сохраняется в requestedPrompt/generatedPrompt; ожидающие задачи завершаются с исходным снимком. Описание вместе со стилем ограничено 2000 символами, превышение отклоняется без запроса. В новых планах Intl.Segmenter выделяет предложения, слишком длинные фрагменты делятся по словам и группируются максимум в шесть кадров по умолчанию. Смещения проверяются относительно неизменённой нормализованной озвучки. Старые планы не перестраиваются.

На 18 октября 2026 общая граница `production/image-adapter.ts` включает проверку подключения, отправку запроса и проверку асинхронной задачи. Ответ — готовые байты JPEG/PNG либо сохранённая задача. `image-catalog.ts` содержит публичные названия/модели/оценки, `image-registry.ts` связывает их с серверными адаптерами BFL и Cloudflare SDXL. Секреты доступны только серверу и обработчику. Новый сервис требует своего адаптера, записи каталога/реестра, конфигурации и контрактных тестов; монтаж менять не нужно. Универсальный переключатель произвольных API без адаптации не заявляется. Озвучка по-прежнему требует аудио с совместимыми таймингами; видеоанимация не подключена.

Выбор `imageProvider` фиксируется в сборке; новые сборки используют `none`, отсутствие поля в старой схеме 1 трактуется как BFL. Переключение под блокировкой/ревизией запрещено во время работы и сохраняет готовые файлы. `provider` у результата и `requestedProvider` у незавершённого запроса разделены: проверка продолжается у исходного сервиса даже после выбора другого. Источник успешного изображения обновляется только вместе с новым файлом. Попытки сохраняют провайдера, модель и оценку. Серверные действия сохраняют проверку владельца/проекта/версии; URL проверки и ID задач не передаются клиенту.

Cloudflare возвращает PNG синхронно; BFL использует асинхронные задачи. Нет автоматических повторов и перехода между сервисами. Даже нулевая оценка требует флага генерации и явного подтверждения; отключённая генерация блокирует бесплатный API тоже. Проверка каталога Cloudflare не отправляет промпт и не доказывает доступ к генерации или квоте. Неопределённый результат POST не запускается повторно автоматически. Файловый маршрут допускает PNG с соответствующим Content-Type; FFmpeg принимает смешанные JPEG/PNG.

## Кадры внутри эпизодов

scene_shots хранит id, scene_id, script_version_id, position, narration_excerpt, action, visual_prompt, duration_seconds, source. Составной FK связывает сцену и версию, RLS разрешает чтение владельцу. Прямые записи закрыты; save_scene_shots проверяет владельца, сцену, версию, все поля и ID, затем атомарно сохраняет порядок и стабильные ID. Позиции сцен/кадров имеют отложенную уникальность для перестановок. Старые функции заменены на месте с защитой от удаления кадров; старые строки не переписаны.

scene_shot_plans хранит снимок озвучки эпизода при последнем сохранении плана. Если она меняется, UI и архив показывают необходимость сверки. RPC отклоняет сохранение по устаревшему тексту эпизода. Это не полная защита от одновременной правки самого списка кадров: рекомендуется одна вкладка. Новая версия не наследует кадры. Удаление эпизода каскадно удаляет его кадры только после явного подтверждения.

Пределы: 40 кадров/эпизод, 240/версия; фрагмент и действие 1–1000 символов, промпт 1–2000, длительность целое 1–60 сек.; JSON до 512 КиБ. Версия блокируется через проект на время записи, чтобы параллельные запросы не обошли общий лимит. Истории правок и автоматической генерации кадров нет.

Экспорт отдельно предлагает промпты сцен и промпты кадров. Порядок кадров: позиция эпизода, затем позиция кадра. Архив включает оба уровня, источники, длительности и сохранённый темп; проверяются связи версии и сцены. Ошибка чтения кадров блокирует экспорт вместо неполного архива.


## MP4-клипы и Runway OAuth — 19 октября 2026

Схема локальной задачи остаётся 1. Необязательные поля VideoShot.visual и clip отделяют выбранный материал от изображения. clip содержит серверное имя файла, длительность, source=upload и tail=hold/loop. Старые задачи используют картинку. Общая проверка hasVisual используется для готовности, бюджета и пропуска генерации изображений; незавершённые запросы проверяются у исходного сервиса. Импорт не выдаётся за генерацию Runway. Оба материала сохраняются при переключении.

POST clips/[jobId] проверяет Origin, авторизованного владельца проекта/версии, ревизию и статус до чтения тела; ограничивает размер 32 МиБ и время загрузки минутой. Перед записью задачи повторная проверка под edit.lock; ffprobe проверяет локальный MP4, время и разрешение, сетевые протоколы запрещены. editJob теперь ожидает асинхронное изменение под блокировкой. Выдача клипа идёт через прежний защищённый маршрут с allowlist файлов. FFmpeg приводит кадры к 720p/24 fps и длине сцены, использует явную политику hold/loop и исключает аудио клипа. Сборка по-прежнему ограничена 5000 символами и 900 секундами; часовые видео не реализованы.

Runway изолирован в runway-connect.ts: фиксированный официальный HTTPS-хост, discovery метаданных, динамическая регистрация публичного клиента, OAuth authorization code + PKCE S256, одноразовый state с HttpOnly/SameSite=Lax cookie, десятиминутный срок входа. Callback фиксирован на loopback 127.0.0.1:3000, повторно проверяет текущего пользователя и версию. Токены и каталог хранятся по ownerId вне public/git, в .connections; клиент получает только статус, время проверки и имена инструментов. Отдельного шифрования файлов токенов пока нет. Отключение локальное, не удалённый OAuth revoke.

Проверка MCP поддерживает JSON и SSE-ответы Streamable HTTP, сессию, ограниченную пагинацию и обновление истёкшего токена. Разрешены только initialize, notifications/initialized, tools/list. tools/call отсутствует: генерация, квота и списания не проверяются. Тексты ошибок провайдера не отображаются; URL назначения фиксирован, редиректы запрещены. Это подготовка будущего адаптера анимации, а не готовый автоматический Runway-пайплайн. Для Veo можно импортировать MP4; программного подключения Flow в этом шаге нет.


### Исправление границы доступа и загрузки

Загрузка сравнивает Origin с HTTP Host запроса для разрешённых loopback-адресов localhost/127.0.0.1/[::1], включая порт; request.url может содержать внутренний адрес Next. Forwarded-заголовки не используются; чужой сайт, другой порт и отсутствующий Origin отвергаются. Проверки пользователя, владельца, версии, ревизии и блокировки остаются обязательными.

Общий серверный транспорт Supabase и proxy устанавливают cache=no-store и тайм-аут 15 секунд на отдельный HTTP-запрос с сохранением отмены вызывающей стороны. Повторов транспорт не добавляет; внутреннее поведение SDK не заменено. Общая операция с несколькими запросами может занимать больше 15 секунд. Ошибки проверки доступа выдаются как VideoAccessError: действия возвращают понятное сообщение, маршруты загрузки/выдачи материалов — 503. Next redirect/notFound пробрасываются через unstable_rethrow и не маскируются. Фоновый опрос видео выполняется последовательно: 4 секунды после ответа для работающей задачи, 30 секунд для простоя; при локальном действии, правке или скрытой вкладке новые опросы приостанавливаются.

Runway не запрашивает сохранённый статус автоматически при открытии страницы. Кнопка подключения доступна без известного статуса; чтение сохранённого подключения выполняется отдельной кнопкой, занятость объясняется. FlowHandoff передаёт только скачиваемое изображение и шаблон промпта через действия пользователя. Ключи Google, cookies браузера и недокументированные endpoints Flow не используются; импорт по-прежнему помечен upload, авторство модели автоматически не приписывается.


## Поиск и страницы библиотеки

/projects принимает q (название, до 120 символов) и page (положительное целое, до пяти цифр). Некорректные/повторяющиеся параметры нормализуются. Запрос остаётся ограничен owner_id и RLS; ILIKE получает литеральный текст с экранированными %, _ и обратной косой чертой. Получаются 13 строк для страницы из 12 и признака следующей; целиком библиотека и тексты сценариев не загружаются. Порядок updated_at DESC, id DESC; вложенная последняя версия ограничена одной записью. Ссылки страниц сохраняют поиск, новый поиск начинает с первой страницы. Пустая страница после первой перенаправляет на первую с тем же поиском. Это offset-пагинация: параллельное изменение проектов может сдвинуть состав соседних страниц.

Удаление по-прежнему выполняется существующим серверным действием с явным подтверждением и owner_id/RLS. Ссылка из карточки лишь открывает настройки у #delete-project. Форма называет проект и перечисляет последствия; локальные видео не удаляются. Схема БД и процедура удаления не менялись.
