# Архитектура ScenePilot

## Стек и границы

Одно приложение Next.js App Router + TypeScript содержит интерфейс и серверные действия. Supabase предоставляет Auth и PostgreSQL с RLS. YandexGPT вызывается только сервером. Локальному приложению нужен интернет для облачных операций. Отдельных backend-сервисов, ORM, очередей и локальной БД нет.

В интерфейсе один «ролик» соответствует записи projects. Термины проекта и ролика не означают разные сущности.

## Модули

| Модуль | Ответственность |
| --- | --- |
| src/app, src/components | Страницы, формы, состояние редакторов, общий ProjectWorkspace |
| src/proxy.ts, src/lib/supabase | Обновление сессии и серверный клиент Supabase |
| src/lib/projects/server.ts | getUser, проверка входа и общие операции доступа |
| src/app/projects/actions.ts | Создание, изменение и удаление собственных проектов |
| src/app/projects/[id]/scripts | Сохранение версии и генерация сценария |
| src/app/projects/[id]/scenes | Генерация и атомарное сохранение набора сцен |
| src/lib/scene-editing.ts | Добавление, перестановка, удаление черновых сцен и выделение разрешённых полей для записи |
| src/app/projects/[id]/publication, src/lib/publication.ts | Проверка владельца/версии, подготовка и сохранение заголовков и описания |
| src/lib/ai | Серверная конфигурация, HTTP-адаптер, проверка ответа Yandex |
| src/lib/export.ts | TXT/Markdown из разрешённых сервером сохранённых данных |
| src/app/projects/channel, src/lib/channel.ts | Один профиль на аккаунт, валидация и вывод копии требований |
| src/app/projects/new/ideas.ts, src/lib/ideas.ts | Проверка задания и профиля, тестовые варианты и проверка JSON идей |
| supabase/migrations | Схема, права, RLS и функции записи |

## Данные

Пользователь → проекты → версии сценария → сцены.

- projects: владелец, название, тема, жанр, стиль, язык, целевая длительность, даты.
- После миграции 202610150001: projects.channel_snapshot — копия профиля при создании, brief_source — источник замысла (manual/test/yandex/unknown). Старые проекты получают null и unknown без переписывания текста.
- channel_profiles: одна строка на owner_id, название канала, аудитория, темы, тон, формат, нежелательные обороты, язык, updated_at. Собственный профиль читается/изменяется через сервер и RLS; owner_id менять запрещено.
- script_versions: проект, уникальный номер в проекте, текст, снимок настроек, источник, дата. Источники: manual, test, yandex, unknown для старых записей.
- scenes: версия сценария, позиция, описание, визуальный промпт, озвучка, источник manual/test/yandex. Источник хранится в каждой строке scenes, а не отдельным полем набора или версии.
- publication_materials: одна строка на script_version_id, выбранный title, массив titles (0–3), description, source manual/test/yandex, updated_at. Каскадно удаляется вместе с версией. Материалы изменяемы, текст и снимок самого сценария остаются неизменными.

Снимок содержит title, topic, genre, style, language и target_duration_seconds. После новой миграции будущие версии также получают channel и brief_source из проекта. Его создаёт БД одновременно с версией из текущих настроек проекта. Старые снимки без этих полей по-прежнему читаются и экспортируются.

## Обязательные инварианты

1. Текст и снимок сохранённой версии не изменяются. Сохранение правки создаёт новую версию; номер назначается в БД под блокировкой проекта.
2. Новая версия не наследует сцены автоматически. Все сцены принадлежат конкретной script_version_id.
3. Сцены внутри версии редактируемы. Редактор вызывает save_scene_edits: функция проверяет владельца, блокирует проект, проверяет источники и заменяет непустой набор через save_test_scenes. Пустой набор удаляет сцены только выбранной версии под той же проверкой и блокировкой. Замена и источники записываются одной транзакцией; ошибка не оставляет частичную запись. Старые save_scenes/save_test_scenes совместимы с прежними вызовами.
4. История правок сцен не ведётся. Экспорт старого сценария использует текущий сохранённый набор его сцен, а не исторический снимок набора.
5. Экспорт содержит текст и настройки выбранной версии, только её сцены и материалы публикации. Несохранённый редактор и текущие настройки проекта в файл не входят.
6. Владелец берётся из сессии, не из браузера. Сервер проверяет проект и принадлежность версии, RLS повторяет ограничения при обращении к БД.
7. Внешние ключи и уникальные позиции обеспечивают связи; подтверждённое удаление проекта каскадно удаляет версии и сцены.
8. Источник материала сохраняется при ручной правке. Это метаданные происхождения, не криптографическое доказательство: допустимый source передаётся при сохранении авторизованным клиентом.
9. Снимок профиля присваивает BEFORE INSERT триггер проекта из собственного channel_profiles. Клиенту не выданы права вставки/изменения channel_snapshot. Изменение профиля не меняет существующие проекты и версии; автоматического переноса новых требований в старый ролик нет.
10. Материалы публикации читаются через RLS владельца проекта, записываются только через save_publication_materials с проверкой auth.uid(), принадлежности версии и блокировкой проекта. Прямая запись в таблицу закрыта. Сервер дополнительно проверяет пару projectId/versionId. Новая версия не наследует описание и заголовки.

## Профиль и помощник замысла

Профиль необязателен, но схема миграций профиля нужна для страницы создания. Основной язык предварительно заполняет язык ролика. Формат и тон заполняют жанр и стиль только если укладываются в предел этих коротких полей — 100 символов. Иначе поля остаются для ручного ввода, а тестовые идеи получают стандартные короткие значения. Подробные требования сохраняются целиком в снимке профиля. При генерации приоритет имеют явные настройки ролика. Аудитория, темы и нежелательные обороты передаются как дополнительные требования.

Помощник получает направление до 1000 символов, язык и длительность 1–300 секунд. Сервер берёт профиль только по owner_id из сессии и сравнивает updated_at с прочитанным формой значением: при обнаруженном изменении предлагает обновить страницу до запроса/создания. Это не полноценная блокировка конкурентной работы: рекомендуется одна вкладка. В модель попадают только разрешённые творческие поля, без owner_id и updated_at.

Результат — ровно три варианта title/topic/genre/style. Лишние идентификаторы от модели отбрасываются, неправильный JSON или размеры отклоняются. Выбор варианта с подтверждением заменяет поля формы; пользователь редактирует их и отдельно создаёт ролик. При ошибке новые данные не заменяют форму. Изменение языка/длительности после получения вариантов блокирует их применение до согласования параметров. Источник замысла не меняется от ручных правок; он не подменяет источник сценария.

Требования канала передаются в реальный генератор сценария из проекта, в генераторы сцен и публикации — из снимка выбранной версии. Экспорт включает эту копию и источник замысла. Тестовые идеи — механические шаблоны, не исследование темы и не обещание успеха.

## Управление сценами

Редактор хранит временные стабильные ключи карточек, чтобы перестановка не смешивала текст полей. Ключи, клиентские позиции и идентификаторы не передаются в запись: сервер выделяет только description, visual_prompt, narration, source. База назначает позиции 1..N из порядка массива. Новая сцена получает manual, генерация — test/yandex; редактирование и перестановка сохраняют источник. Источник — метаданные происхождения, не доказательство авторства.

Добавление, удаление и порядок меняют локальный черновик; запись происходит одной кнопкой. Удаление карточки требует подтверждения, сохранение пустого набора — дополнительного подтверждения очистки. Генерация по-прежнему требует 1–12 заполненных сцен, а ручной редактор сохраняет 0–12. Три поля обязательны для каждой непустой сцены. Истории и автоматического восстановления удалённых сцен нет. Экспорт и библиотека обновляются после сохранения; другие версии и сценарий не изменяются.

## Материалы публикации

Вкладка использует только сохранённый сценарий и его снимок, не несохранённый редактор, текущий профиль или сцены. Генератор получает whitelist творческих полей без идентификаторов владельца. Результат Yandex — ровно три разных заголовка и описание; неверный/оборванный ответ отклоняется без повтора и подмены шаблоном. Первый вариант подставляется в выбранный заголовок; его можно выбрать заново или изменить отдельно. Ручной ввод требует только заголовок и описание, варианты необязательны. Тестовый режим показывает явно обозначенный шаблон с фрагментом сценария, не выдаёт его за пересказ или исследование.

Генерация заменяет редактор после подтверждения. Сохранение выполняет upsert разрешённых полей через RPC и не вызывает модель. Источник набора сохраняется при ручных правках. Экспорт загружает только сохранённую строку выбранной версии; ошибка загрузки блокирует файл вместо молчаливой потери раздела. Отдельные кнопки копируют текущий текст редактора, включая несохранённый. Истории правок и защиты от перезаписи другой вкладкой нет; рекомендуется одна вкладка.

## Навигация по материалам

Библиотека /projects получает последнюю версию каждого собственного проекта и число её сцен без загрузки текстов. Из неё доступны прямые переходы к материалам.

Общий серверный компонент ProjectWorkspace показывает название ролика, выбранную версию и ссылки «Настройки / Сценарий / Сцены / Публикация / Экспорт». Он получает версию после проверки страницей. При переходах version остаётся в query string. Настройки без version выбирают последнюю версию, с version проверяют её принадлежность проекту. Редактирование, отмена и сохранение настроек сохраняют контекст версии; navigationVersion служит только для адреса возврата, не для записи данных.

Без сохранённого сценария сцены, публикация и экспорт недоступны, причина видна в панели. История версий находится в редакторе сценария. Ошибочный или чужой идентификатор не переключает пользователя молча на другую версию.

## Генерация и сохранение

- Сценарий: текущие настройки проекта → проверка доступа → тестовый генератор или Yandex → проверка результата → редактор → отдельное сохранение версии.
- Сцены: сохранённый текст выбранной версии и её снимок → проверка доступа → генератор → валидация всего набора → редактор → отдельное сохранение сцен.
- Ошибка запроса оставляет редактор без замены. Сохранение не вызывает модель. Автоматических повторов и скрытого тестового ответа нет.
- Yandex использует server-only, фиксированный HTTPS endpoint, no-store и x-data-logging-enabled:false. Email, сессия и секреты не включаются в промпт; тело ошибок API не показывается пользователю.

## Текущие пределы

Материалы публикации: заголовок и каждый вариант до 100 символов, описание до 5000, до трёх вариантов; модель должна вернуть ровно три разных. Вход Yandex — до 30 000 символов JSON, выход — до 2000 токенов. Лимиты приложения повторены в проверке RPC; это не проверка фактической достоверности или гарантия качества для YouTube.

Профиль: название до 120, аудитория до 400, темы/тон/формат/нежелательные обороты до 1000 символов каждое. Лимиты формы и серверной проверки задаёт channelLimits, ограничения базы обновляет отдельная миграция 202610150002_channel_profile_limits.sql. При их изменении нужно согласовывать оба уровня.

Длительность проекта 1–300 секунд; сценарий до 20 000 символов; до 12 сохранённых сцен с тремя обязательными полями до 2000 символов каждое. Языки ru/en. Запрос сценария: до 6000 символов JSON без профиля или 9000 с профилем; до 2000 токенов ответа. Запрос сцен: до 24 000 символов JSON без профиля или 27 000 с профилем; до 4000 токенов ответа. Запрос идей: до 6000 символов JSON и 2000 токенов ответа. Тайм-аут 45 секунд, автоматических повторов нет. Длительность — ориентир, не точный хронометраж.

Нет автосохранения черновиков, истории правок сцен, защиты от конфликтов вкладок и денежной блокировки бюджета. Полный список ограничений и проверки — в [testing.md](testing.md).
