# Архитектура ScenePilot

## Стек и границы

Одно приложение Next.js App Router + TypeScript содержит интерфейс и серверные действия. Supabase предоставляет Auth и PostgreSQL с RLS. YandexGPT вызывается только сервером. Локальному приложению нужен интернет для облачных операций. Отдельных backend-сервисов, ORM, очередей и локальной БД нет.

В интерфейсе один «ролик» соответствует записи projects. Термины проекта и ролика не означают разные сущности.

## Модули

| Модуль | Ответственность |
| --- | --- |
| src/app, src/components | Страницы, формы, состояние редакторов, общий ProjectWorkspace |
| src/proxy.ts, src/lib/supabase | Обновление сессии и серверный клиент Supabase |
| src/lib/projects/server.ts | getUser, проверка входа и общие операции доступа |
| src/app/projects/actions.ts | Создание, изменение и удаление собственных проектов |
| src/app/projects/[id]/scripts | Сохранение версии и генерация сценария |
| src/app/projects/[id]/scenes | Генерация и атомарное сохранение набора сцен |
| src/lib/ai | Серверная конфигурация, HTTP-адаптер, проверка ответа Yandex |
| src/lib/export.ts | TXT/Markdown из разрешённых сервером сохранённых данных |
| supabase/migrations | Схема, права, RLS и функции записи |

## Данные

Пользователь → проекты → версии сценария → сцены.

- projects: владелец, название, тема, жанр, стиль, язык, целевая длительность, даты.
- script_versions: проект, уникальный номер в проекте, текст, снимок настроек, источник, дата. Источники: manual, test, yandex, unknown для старых записей.
- scenes: версия сценария, позиция, описание, визуальный промпт, озвучка, источник test/yandex и даты. Источник сцен хранится в строках scenes, а не отдельным полем версии.

Снимок содержит title, topic, genre, style, language и target_duration_seconds. Его создаёт БД одновременно с версией из текущих настроек проекта.

## Обязательные инварианты

1. Текст и снимок сохранённой версии не изменяются. Сохранение правки создаёт новую версию; номер назначается в БД под блокировкой проекта.
2. Новая версия не наследует сцены автоматически. Все сцены принадлежат конкретной script_version_id.
3. Сцены внутри версии редактируемы. save_scenes проверяет набор и заменяет его одной транзакцией через существующую функцию save_test_scenes; ошибка не оставляет частичную запись.
4. История правок сцен не ведётся. Экспорт старого сценария использует текущий сохранённый набор его сцен, а не исторический снимок набора.
5. Экспорт содержит текст и настройки выбранной версии и только её сцены. Несохранённый редактор и текущие настройки проекта в файл не входят.
6. Владелец берётся из сессии, не из браузера. Сервер проверяет проект и принадлежность версии, RLS повторяет ограничения при обращении к БД.
7. Внешние ключи и уникальные позиции обеспечивают связи; подтверждённое удаление проекта каскадно удаляет версии и сцены.
8. Источник материала сохраняется при ручной правке. Это метаданные происхождения, не криптографическое доказательство: допустимый source передаётся при сохранении авторизованным клиентом.

## Навигация

Библиотека /projects получает последнюю версию каждого собственного проекта и число её сцен без загрузки текстов. Из неё доступны прямые переходы к материалам.

Общий серверный компонент ProjectWorkspace показывает название ролика, выбранную версию и ссылки «Настройки / Сценарий / Сцены / Экспорт». Он получает версию после проверки страницей. При переходах version остаётся в query string. Настройки без version выбирают последнюю версию, с version проверяют её принадлежность проекту. Редактирование, отмена и сохранение настроек сохраняют контекст версии; navigationVersion служит только для адреса возврата, не для записи данных.

Без сохранённого сценария сцены и экспорт недоступны, причина видна в панели. История версий находится в редакторе сценария. Ошибочный или чужой идентификатор не переключает пользователя молча на другую версию.

## Генерация и сохранение

- Сценарий: текущие настройки проекта → проверка доступа → тестовый генератор или Yandex → проверка результата → редактор → отдельное сохранение версии.
- Сцены: сохранённый текст выбранной версии и её снимок → проверка доступа → генератор → валидация всего набора → редактор → отдельное сохранение сцен.
- Ошибка запроса оставляет редактор без замены. Сохранение не вызывает модель. Автоматических повторов и скрытого тестового ответа нет.
- Yandex использует server-only, фиксированный HTTPS endpoint, no-store и x-data-logging-enabled:false. Email, сессия и секреты не включаются в промпт; тело ошибок API не показывается пользователю.

## Текущие пределы

Длительность проекта 1–300 секунд; сценарий до 20 000 символов; 1–12 сцен с тремя обязательными полями до 2000 символов каждое. Языки ru/en. Запрос сценария: до 6000 символов JSON настроек, до 2000 токенов ответа. Запрос сцен: до 24 000 символов JSON-задания, до 4000 токенов ответа. Тайм-аут 45 секунд. Длительность — ориентир, не точный хронометраж.

Нет автосохранения черновиков, истории правок сцен, защиты от конфликтов вкладок и денежной блокировки бюджета. Полный список ограничений и проверки — в [testing.md](testing.md).
